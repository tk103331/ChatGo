# ChatGo 插件扩展点清单与 ROI 分析

- 日期：2026-11-08
- 配套文档：`2026-11-08-plugin-system-design.md`、`2026-11-08-plugin-extension-points-design.md`

本文穷举当前代码里可承载插件能力的接缝，并对每一项给出实现难度、收益与建议结论。

## 1. 评分口径

**难度 D（1-5）**，看的是“改动面 × 风险”，不是单纯代码量：

| 分值 | 含义 | 典型特征 |
|---|---|---|
| 1 | 极低 | 纯声明、复用现有加载器或列表合并 |
| 2 | 低 | 单点 UI + 单点调度，不动核心数据流 |
| 3 | 中 | 需要新协议/新后端/多处埋点，或改配置模型 |
| 4 | 高 | 涉及网络端点、深改检索/路由、跨系统状态 |
| 5 | 极高 | 需要重构数据模型、UI 渲染层或安全体系 |

**收益 B（1-5）**，同时看用户价值与平台杠杆（能让别的插件做出什么）：

| 分值 | 含义 |
|---|---|
| 5 | 平台核心能力，没有它插件生态不成立 |
| 4 | 解锁一类新用法，或明显减少重复开发 |
| 3 | 有明确场景，但可用现有能力绕开 |
| 2 | 便利性提升，锦上添花 |
| 1 | 有它更好，没它无感 |

**工作量**：S（≈1-3 人日）、M（≈3-7）、L（≈7-15）、XL（≈15-30）。仅为相对量级，不是承诺。

**性价比** = 收益 ÷ 难度，四舍五入为星级：

| 星级 | 含义 |
|---|---|
| ★★★★★ | 立刻做 |
| ★★★★ | 值得做 |
| ★★★ | 按需做 |
| ★★ | 缓做或只做最小版 |
| ★ | 不做 |

## 4. 难度到底难在哪

难度不等于代码行数，四项成本决定分值：

| 成本 | 说明 | 典型扩展点 |
|---|---|---|
| **协议成本** | 一旦发布就要长期兼容，改一次要动插件生态 | 渲染协议、触发器求值、App 视图 |
| **一致性成本** | 要在多条执行路径都埋点，漏一条就是 bug | 事件钩子、工具结果钩子、中间件 |
| **安全成本** | 引入网络入口、文件访问或进程执行，需要评审 | 渠道驱动、上下文提供者、Web API |
| **维护成本** | 上线后持续跟随外部平台变化 | 渠道驱动（平台 API）、Provider（厂商变更） |

据此可以把扩展点分成五档：

1. **声明式注入**（D1）：MCP、Skill、Agent、主题、导入器——只做校验与合并。
2. **列表/菜单合并**（D2）：斜杠命令、通知、统计、导出、菜单——UI 为主。
3. **协议/埋点**（D3）：事件、中间件、上下文、渲染、触发器、路由——难在语义与失败策略。
4. **跨系统**（D4）：渠道、知识库、Web API——难在生命周期、检索路径、鉴权。
5. **平台重写**（D5）：声明式 App、i18n、原生 UI——要先定义一套长期模型。

## 5. 收益到底来自哪

收益要拆成三种，避免只看“用户能不能看见”：

| 收益类型 | 说明 | 典型扩展点 |
|---|---|---|
| **直接价值** | 用户马上能感知 | 工具、上下文、知识库、App、渲染 |
| **平台杠杆** | 让别的插件能做出东西，收益会放大 | 事件钩子、工具结果钩子、Provider、Middleware、导入器 |
| **分发/生态** | 降低插件作者的交付成本 | Agent、主题、斜杠命令、安装器 |

**杠杆系数**：一个扩展点的实际收益 ≈ 直接价值 × 它解锁的扩展点数量。

- 事件钩子：直接价值 3，但解锁通知、审计、外部触发器 → 实际 4。
- 渲染协议：直接价值 2，但解锁声明式 App → 实际 3。
- 宿主 HTTP 端点：直接价值 1，但解锁 Webhook 触发器与渠道驱动 → 实际 3。
- 声明式 App：直接价值 4，但依赖渲染协议，且自身协议难改 → 风险调整后 3。

## 7. 分目标的最短路径

| 目标 | 建议先做 | 说明 |
|---|---|---|
| 插件生态能跑起来 | 工具 → Agent → MCP/Skill → 主题 → 安装器 | 先把 P0 做完整 |
| 企业集成 | 事件钩子 → 工具结果钩子 → 导入器 → 渠道驱动 | 审计与外部系统优先 |
| 个人效率 | 斜杠命令 → 上下文提供者 → 通知 → 任务触发器 | 全部是“输入/提醒”侧改进 |
| 高质量问答 | 上下文提供者 → 知识库管线 → 渲染 | 先解决数据进入，再解决展示 |
| 自动化平台 | 事件钩子 → 任务触发器 → Webhook 端点 → 渠道 | 触发器与渠道共用端点 |

## 8. 结论

- **最划算的不是“功能最多”的扩展点，而是“让别人能扩展”的扩展点**：事件钩子、工具结果钩子、导入器、渲染协议。
- **最容易被低估的是维护成本**：渠道驱动和 Provider 上线后要跟随外部平台变化，而它们的分值里没有体现这一点。
- **最容易被高估的是声明式 App**：想象空间大，但它依赖渲染协议、协议难改、开发量最大，应放在最后。
- 如果只能投入一个迭代：**先做工具 + Agent（零成本）**，同时补**事件钩子**（杠杆最高），这三项就能覆盖大部分插件场景。
